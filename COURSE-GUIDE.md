# Course guide

This course organizes the actual AI learning journey into 13 chapters. The Learning Hub's own construction and release are project history, not chapter 14.

The app teaches use of real AI chats, file tools, browsers, coding environments, and connected services. It supplies context, preparation, practice prompts, inspection checks, questions, and reference. It does not replace those tools with an embedded AI coach.

## Chapters

| Chapter | What you learn |
|---|---|
| 01. Models, tools, and skills | Create/edit the first note, inspect it, and identify the roles. |
| 02. Files, context, and continuity | Supply the note, check a source-based answer, save instructions/progress, and resume in another chat. |
| 03. Ask, steer, and verify | Direct useful work without needing a perfect first prompt. |
| 04. Research with evidence | Find an answer, open its sources, and preserve what you verified. |
| 05. Create useful artifacts | Work with files and visuals, then inspect the actual result. |
| 06. Show AI what you see | Distinguish a snapshot, a browser connection, and authorized computer actions. |
| 07. Plugins, MCP, and reusable skills | Know what extends the assistant and what grants access. |
| 08. Plans, goals, schedules, and chat controls | Choose the right control for proposing, pursuing, or repeating work. |
| 09. Develop with AI and Git | Direct a small program, review its changes, and save meaningful versions. |
| 10. Collaborate through pull requests | Make the review conversation part of the work. |
| 11. Local, worktree, and cloud | Know where changes live before running concurrent work. |
| 12. Subagents and coordinated chats | Split independent work, make handoffs explicit, and review the combined result. |
| 13. Hooks and cross-product workflows | Automate the right check and recognize related concepts in other tools. |

## Practical evidence and prerequisites

### 3. Ask, steer, and verify

Original journey: Practiced: a vague request became a desktop learning-app brief, and the learner independently supplied audience, purpose, practice, and a quiz. Steering, Stop, caching, and approval-wait behavior were discussed; no token-saving benchmark was performed.

Preparation: A text AI chat. Use the supplied learning-app idea; no coding or paid API is needed. Do not repeat a completed exercise merely to populate this course.

Practice checkpoints:
1. Refine the actual journey request
2. Specify the learning result
3. Give a targeted revision

### 4. Research with evidence

Original journey: Practiced: researched whether Plus includes API usage, saved findings and official links, and opened a supporting source. No API key or billable API request was created.

Preparation: An AI assistant with web search and an internet connection. A text editor or file tool can save the finding. The exercise does not require an API account or payment.

Practice checkpoints:
1. Search official documentation
2. Inspect a source
3. Save the finding

### 5. Create useful artifacts

Original journey: Practiced: PDF/source link, spreadsheet formula and count change, presentation edits and generated logo, calculator sliders, Riyadh markers, and a sketch. Sites completion was learner-reported. Word rendering was deferred; image editing and second-deck template reuse were skipped.

Preparation: An assistant with the relevant file or visual tools and a viewer for the result. Features may require plugins or a supported account. Use fictional sample data. Missing tools can be marked deferred; do not buy software just to tick a box.

Practice checkpoints:
1. Inspect a short PDF
2. Change a spreadsheet input
3. Direct a presentation edit
4. Try an interactive visual
5. Preview a small learning site

### 6. Show AI what you see

Original journey: Practiced: a Notepad Appshot, connected Brave reading/navigation, and harmless text entry in a fresh Notepad window. Hoots was shown and voice replies heard. Mini's resulting UI was not independently confirmed; existing-tab login and extension-store restrictions were encountered.

Preparation: A supported screenshot/Appshot feature, connected browser, and computer tool for desktop practice. The learner handles sign-in and permission prompts. Use a fresh blank note; preserve existing work.

Practice checkpoints:
1. Share a harmless snapshot
2. Read a connected browser tab
3. Observe one computer action

### 7. Plugins, MCP, and reusable skills

Original journey: Practiced: plugin approval inspection, MCP status, a reusable text recap skill, and a private AI Quest Coach plugin tested with notes, a quiz reply, and missing notes. Legacy GPT creation was not practiced; the interface offered plugin creation instead.

Preparation: A client supporting skills or plugins. Account authorization is only needed for external resources you choose. This lesson can use supplied notes without an external account. Creation tools and UI labels vary by product/version.

Practice checkpoints:
1. Inspect one connection
2. Create a bounded recap method
3. Test behavior, including missing input

### 8. Plans, goals, schedules, and chat controls

Original journey: Practiced: Plan mode proposal then implementation; a bounded Goal produced a quiz after UI failures; Side received relevant parent context; Status/MCP/Usage inspected. Scheduling setup was explored, but a saved run and pause were not confirmed. Fork, Fast, and several settings were explanation-only.

Preparation: A supported app/client for the controls. Menu labels and availability vary. The core exercise needs planning and a bounded task; scheduling is an explicitly optional extension, not automatically enabled by reading this chapter.

Practice checkpoints:
1. Inspect controls without changing them
2. Propose a bounded plan
3. Implement only the agreed task

### 9. Develop with AI and Git

Original journey: Practiced: edited and ran a JavaScript tracker, added a lesson and observed the count, used AI-led diffs/staging/commits/branches, and demonstrated a targeted undo. The learner chose AI-led operations; manual terminal commands were optional.

Preparation: A file-capable coding assistant, Node.js and Git in a disposable practice repository. Ask the assistant to inspect prerequisites and install only through the appropriate authorized workflow. No GitHub account is needed for local Git.

Practice checkpoints:
1. Create and run the tiny tracker
2. Change one input and check behavior
3. Save a local version and compare a change
4. Try a targeted undo

### 10. Collaborate through pull requests

Original journey: Practiced: created a private practice repo, pushed branches, opened a draft PR, posted disclosed simulated reviewer feedback, addressed it in another commit, followed up, marked ready, merged, and synchronized locally. The app's public repo later added real CI and releases.

Preparation: A GitHub account and access to a practice repository, plus a local Git working copy or appropriate connected tools. Work only in the learner's chosen repository. Publishing, comments, merge, and deletion are distinct actions; do not affect an unrelated public project.

Practice checkpoints:
1. Publish a reviewed practice branch
2. Open and inspect a draft PR
3. Simulate a disclosed review exchange
4. Understand the maintainer decision

### 11. Local, worktree, and cloud

Original journey: Practiced: an ordinary Git worktree with a visibly different title, a private cloud environment, and a read-only cloud task. The learner checked worktree isolation. App-managed worktrees and actual PC-off continuation were not independently tested.

Preparation: A clean-enough practice Git repository for a worktree. A cloud task needs an accessible published environment and source repository. Cloud accounts, network policy, dependencies, and secrets are separate setup concerns.

Practice checkpoints:
1. Inspect the execution location
2. Create an isolated practice checkout
3. Run a read-only cloud task

### 12. Subagents and coordinated chats

Original journey: Practiced: two parallel read-only subagents, parent synthesis, a specifically selected smaller-model implementation, and a parent-mediated specification handoff between two practice chats. Direct peer messaging and measured cost savings were not demonstrated.

Preparation: A client with subagents or separate-chat coordination, and the practice tracker/README. A smaller-model handoff requires an available model and explicit selection. Separate checkouts are needed for concurrent edits; the first exercise is read-only.

Practice checkpoints:
1. Run two read-only subagents
2. Make a bounded model handoff
3. Coordinate a dependent pair of chats

### 13. Hooks and cross-product workflows

Original journey: Practiced: an ordinary Node syntax-check script, a manually labeled test, a trusted Stop hook, log-based verification after configuration corrections, and disabling the demo. Claude Code/Copilot concepts were compared here; neither product was installed or run by the learner.

Preparation: For actual hooks: supported lifecycle hooks, a practice repository, and the required runtime. Review/trust local configuration through supported controls. Competitor comparisons can be read without subscriptions or installations.

Practice checkpoints:
1. Create and manually test a check
2. Trust and verify one actual lifecycle event
3. Disable the demo and compare a portable task

## Progress and existing experience

Each chapter has separate practical status, quiz attempts, and personal notes. Opening a chapter does not complete it. Earned titles require its practical checks plus all three correct answers. Skip and defer remain distinct from practice.

My journey records previous learning separately, so an experienced learner can preserve real evidence without repeating the course or inventing quiz passes. Ten optional follow-ups preserve the original skipped, explained, and deferred areas:

- Inspect a real scheduled run, then pause it
- Create and inspect a rendered Word recap
- Edit an image when you want to revisit it
- Apply a saved template to new content
- Try an app-managed worktree
- Verify a direct chat-to-chat handoff
- Optionally run the portable review elsewhere
- Observe cloud task continuity
- Inspect Mini's resulting interface
- Try a conversation fork

Resume returns to the saved chapter, section, and practice step. Export/import operates on personal local progress, with a preview before replacement and a local recovery copy. The app does not sync that file to GitHub.
